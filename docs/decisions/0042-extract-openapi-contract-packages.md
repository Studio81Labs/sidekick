# ADR 0042: Extract OpenAPI Contract Packages

Status: accepted

Date: 2026-08-26

## Context

The backend OpenAPI document and its generated TypeScript declarations were
owned by the PWA source tree. Backend contract generation therefore wrote into
an application directory, and other consumers could reach the wire contract
only through an app-relative path. That ownership does not match the Studio81
portfolio boundary used by Nexcue, TableTap, and Tarmoto, and it makes Docker,
CI, and future client generation depend on the PWA layout.

The document is generated by booting the FastAPI application against isolated,
empty storage. Its sorted JSON representation and the exactly pinned
`openapi-typescript` generator are deterministic and already committed for
review. The extraction must retain that property, keep the backend as the
contract source, and avoid introducing runtime code generation.

## Decision

`packages/openapi` owns the committed `openapi.json` document, the Python export
entry point, structural validation, and freshness checks. The FastAPI models and
route annotations remain the authoritative source. The exporter creates the
application against a temporary data directory so generation cannot read or
mutate operator data.

`packages/openapi-client` owns the committed generated TypeScript declarations
and exposes them from `@poker-hero/openapi-client`. Applications depend on that
workspace package and must not import generated contracts through another app's
source tree. The dependency direction is therefore:

```text
FastAPI models/routes
  -> packages/openapi/openapi.json
  -> packages/openapi-client/src/generated/openapi.ts
  -> apps/pwa domain API adapters
```

Generation is explicit through `pnpm api:generate`; it is not a postinstall
hook. `pnpm api:check` first requires both committed artifacts to exist, be
tracked, and be clean, exports the backend document into a temporary directory,
validates and byte-compares it with the committed document, regenerates the
TypeScript client, and rejects staged, unstaged, or untracked output changes.

The reusable `_build-openapi.yml` workflow exports the document from an exact
ref, applies the lockfile-pinned canonical formatter, and publishes a
short-lived artifact. Local freshness checks apply the same canonical formatter
to their temporary export before byte comparison. `openapi-check.yml` consumes
the artifact for the required freshness gate. Application workflows continue
to build from the reviewed committed workspace package; their change selection
includes both contract packages and the shared TypeScript baseline so a
contract-only change cannot bypass PWA, browser, or deployment validation.

The PWA Docker build copies all workspace manifests before the frozen install,
then copies the OpenAPI packages and shared TypeScript configuration before the
production build. No generated contract is downloaded during deployment, and
no production image needs Python merely to build the PWA.

## Consequences

- Backend changes that alter the contract must update two reviewable artifacts.
- The PWA consumes a named workspace boundary instead of app-relative generated
  files.
- CI can distinguish backend emission, generated-client freshness, application
  typechecking, and runtime tests.
- Adding another client generator no longer requires writing into an existing
  application.
- Frozen installs and production builds require the two package manifests and
  sources to be present in their Docker build context.
- The committed artifacts remain part of the trusted source tree and must pass
  the repository supply-chain and review controls.

## Rollout And Rollback

The rollout moves the existing byte-identical artifacts, updates imports and
workspace metadata, then enables the always-emitted OpenAPI gate on `main` only
after that workflow exists on the default branch. The PWA, backend, browser
suite, and both root-context Docker builds must remain green before merge.

Rollback is one atomic revert of this migration: restore the exporter and
generated files below `apps/pwa`, restore relative imports and Docker inputs,
and remove the OpenAPI required check before removing its workflow. Backend API
or persistence compatibility is unaffected because the wire document and
runtime behavior do not change.
